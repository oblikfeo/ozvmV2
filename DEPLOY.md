# Разворот на поддомене

Розничная часть — статический сайт: HTML, CSS, JS и картинки. Ни сборки,
ни Node, ни PHP на ней нет. Разворот сводится к тому, чтобы положить папку
на сервер и показать на неё nginx.

Боевой `ozvm.ru` (Next.js в контейнере) и `api.ozvm.ru` (Laravel) при этом
не трогаются: общего кода нет, общий только сервер.

---

## 0. Что выкладываем

| Адрес | Страница |
|---|---|
| `/` | Лендинг компании |
| `/promotion.html?id=N` | Страница одной акции |
| `/index.html` | Витрина акций |
| `/admin.html` | Админка: акции и контент лендинга |
| `/design-system.html` | Стайлгайд |

Корень поддомена отдаёт лендинг — так задано в конфиге nginx, файлы лежат
там же, где в репозитории.

---

## 1. Подготовка

1. **Выбрать поддомен.** Дальше в примерах `shop.ozvm.ru`. Заменить его нужно
   в одном месте — `deploy/nginx/retail.conf`, директива `server_name`.

2. **A-запись в DNS:** `shop` → IP боевого сервера. Проверить:

   ```bash
   dig +short shop.ozvm.ru
   ```

   Пока запись не разошлась, certbot сертификат не выпустит.

---

## 2. Вариант А — статикой в /var/www (рекомендуемый)

Ничего не контейнеризуем: nginx хоста сам отдаёт файлы.

```bash
# 1. Забрать код
git clone https://github.com/oblikfeo/ozvmV2.git /var/www/ozvm-retail
cd /var/www/ozvm-retail

# 2. Права: nginx должен читать файлы
chown -R www-data:www-data /var/www/ozvm-retail

# 3. Конфиг сайта
cp deploy/nginx/retail.conf /etc/nginx/sites-available/ozvm-retail.conf
# заменить shop.ozvm.ru на свой поддомен
nano /etc/nginx/sites-available/ozvm-retail.conf
ln -s /etc/nginx/sites-available/ozvm-retail.conf /etc/nginx/sites-enabled/

# 4. Пароль на админку
htpasswd -c /etc/nginx/.htpasswd-ozvm-retail admin

# 5. Проверить и применить
nginx -t && systemctl reload nginx
```

## 2б. Вариант Б — контейнером

Если удобнее держать сайт рядом с `ozvm.ru` в Docker:

```bash
cd /var/www/ozvm-retail
docker compose -f deploy/docker-compose.yml up -d --build
```

Контейнер слушает `127.0.0.1:8081`. Публичный 80/443 остаётся на nginx хоста,
он проксирует поддомен внутрь:

```nginx
location / {
    proxy_pass http://127.0.0.1:8081;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
```

Минус варианта: после каждой правки нужна пересборка образа. Для статики,
которая меняется часто, вариант А удобнее.

---

## 3. HTTPS

```bash
certbot --nginx -d shop.ozvm.ru
```

Certbot сам допишет в конфиг блок на 443 и редирект с 80. Автопродление
проверяется так:

```bash
certbot renew --dry-run
```

---

## 4. Обновление после правок

```bash
cd /var/www/ozvm-retail && git pull
```

Перезапускать nginx не нужно — он отдаёт файлы с диска. HTML отдаётся
с `Cache-Control: no-cache`, css и js — с часовым кешем, поэтому правки
стилей видны сразу или в пределах часа. Если нужно немедленно, дописать
к ссылке на css версию (`?v=2`) или сбросить кеш в браузере.

## 5. Проверка после выкладки

- [ ] `https://shop.ozvm.ru/` открывает лендинг
- [ ] `/index.html` открывает витрину акций, карточки кликаются
- [ ] `/admin.html` спрашивает пароль nginx, после него — вход админки
- [ ] в админке сохраняется акция и её видно на витрине
- [ ] в админке сохраняется правка лендинга и её видно на `/`
- [ ] «Личный кабинет партнёра» и «Получить доступ к оптовым ценам»
      ведут на `ozvm.ru`
- [ ] несуществующий адрес отдаёт 404-страницу, а не страницу nginx
- [ ] сертификат валиден, `http://` редиректит на `https://`

## 6. Ограничения текущей версии

Это надо понимать до показа клиенту.

**Данные живут в браузере.** Акции и контент лендинга лежат в `localStorage`
того, кто их сохранил. У каждого посетителя своя копия: правки администратора
не видны никому, кроме него самого, и пропадут при очистке браузера.
Пока это витрина, а не работающая CMS.

**Вход в админку — демонстрационный.** Логин и пароль зашиты в `js/auth.js`
открытым текстом, любой может прочитать их в исходниках страницы. Basic auth
на nginx — единственная реальная защита, и она обязательна.

Оба пункта снимаются одной задачей: перенести хранилища на API (см. ниже).

## 7. Следующий шаг — каталог на API основного проекта

CORS на `api.ozvm.ru` открыт (`Access-Control-Allow-Origin: *`), поэтому
поддомен ходит в API из браузера без правок на бэкенде.

Что уже готово к этому в коде:

- `js/config.js` — адрес API и внешние ссылки в одном месте
- `js/api.js` — обёртка над fetch: базовый адрес, заголовки, Bearer-токен,
  разбор ошибок. Пока не используется, написана под каталог
- `js/store.js` и `js/landing-store.js` — вся работа с данными изолирована
  в них, страницы дёргают только их методы. Меняется тело функций, вёрстка нет

Готовые ручки API (`routes/api.php` основного проекта):

| Ручка | Назначение |
|---|---|
| `GET /api/v1/shop/categories` | категории |
| `GET /api/v1/shop/manufacturers` | производители |
| `GET /api/v1/shop/products` | список товаров |
| `GET /api/v1/shop/products/{slug}` | карточка товара |
| `POST /api/v1/shop/checkout` | оформление заказа |
| `GET/POST/PATCH/DELETE /api/v1/cart` | корзина (нужен токен) |
| `POST /api/v1/user/login` | вход |
| `POST /api/v1/user/registration` | регистрация |
| `GET /api/v1/user`, `/api/v1/user/orders` | профиль и заказы (нужен токен) |

Чего в API пока нет и что придётся добавить на стороне Laravel:

- **акции** — таблица `promotions` и роуты под неё
- **контент лендинга** — хранилище под тексты и картинки блоков
- **права администратора** — сейчас `auth:sanctum` не отличает админа
  от обычного клиента

Токен кладётся в `localStorage` под тем же ключом `USER_TOKEN`, что
в основном проекте: если однажды розницу и опт сведут на один домен,
сессия окажется общей.
